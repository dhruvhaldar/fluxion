## 2026-07-19 - [Fix Log Bombing / Disk DoS via Content-Length Validation]
**Vulnerability:** A vulnerability existed where an unvalidated Content-Length header check preceded IP validation/normalization and immediately triggered an un-rate-limited warning log (`app.logger.warning`). By sending repeated requests with excessively large payloads, an attacker could bypass rate limits (as the requests were blocked and logged before tracker increments) and easily cause a Disk DoS via log bombing.
**Learning:** Security validations that result in log entries must be positioned after input sanitization/normalization or else the raw inputs must not be logged directly. Additionally, early blocks must still participate in a rate-limiting scheme to avoid filling up the disk with duplicate security event logs from steady-rate attacks.
**Prevention:** Always normalize tracking keys (like `ip`) *before* executing security checks that result in a log entry. When throwing early block errors, use a tracker (like `log_early_block`) instead of raw un-rate-limited logging to coalesce identical warnings.
