## 2026-07-21 - Force Connection Closure on Payload Too Large
**Vulnerability:** A resource exhaustion Denial of Service (DoS) vulnerability existed when manually returning a 413 Payload Too Large error early in the request lifecycle without forcing the connection to close. Because HTTP/1.1 connections default to keep-alive, an attacker could continue streaming a massive payload on the open socket even after receiving the 413, tying up server resources.
**Learning:** When a Flask application enforces a `Content-Length` check and attempts to abort the request via an early return (e.g., in `@app.before_request`), Werkzeug/Flask does not automatically close the underlying TCP connection if the client ignores the response and keeps sending data.
**Prevention:** Always explicitly include the `{"Connection": "close"}` HTTP header when returning manual 413 responses. This instructs the application server (e.g., Gunicorn or the development server) to forcibly terminate the TCP connection immediately after sending the error response, ensuring the server does not waste resources receiving the remainder of the oversized payload.
